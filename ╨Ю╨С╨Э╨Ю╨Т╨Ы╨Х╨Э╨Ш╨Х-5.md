# Обновление 5: личный кабинет

Распаковать поверх папки `ka_trainer`. Проверка (должно быть `True`):

```powershell
Test-Path trainer\accounts.py, trainer\templates\trainer\profile.html, trainer\migrations\0002_gameresult_user_courseprogress.py
```

Локально:

```powershell
venv\Scripts\python.exe -m pip install -r requirements.txt
venv\Scripts\python.exe manage.py migrate
venv\Scripts\python.exe manage.py runserver
```

`pip install` нужен — появились две новые зависимости (о них ниже).
`migrate` тоже обязателен: в базе появляются два новых поля.

## Что появилось

- `/registraciya/` — регистрация: только имя и пароль, почта не спрашивается.
- `/vhod/` — вход, `/kabinet/` — профиль.
- В меню тренажёра справа — «Войти» или имя пользователя. В меню курса — «👤 Кабинет».

**В кабинете:** очки всего, сколько уроков сыграно, серия дней подряд, сколько тем курса
отмечено, таблица по каждой игре и кнопка выхода.

**Очки, набранные до регистрации, не пропадают.** При входе или регистрации результаты
текущей сессии браузера переносятся на аккаунт — переносить руками ничего не нужно,
в кабинете будет строчка о том, сколько результатов переехало.

**Галочки на тропе теперь общие для всех устройств.** Раньше они лежали только
в localStorage браузера. Для вошедшего пользователя те же отметки хранятся в базе:
страница курса при загрузке спрашивает их у сервера, а при каждом изменении отправляет
обратно. Первый вход поднимает на сервер то, что уже накопилось в браузере. Для гостя
всё работает как раньше — localStorage и никаких аккаунтов.

## Обязательно: Postgres на Render

**Без этого кабинет бессмысленен.** На бесплатном тарифе Render файловая система
пересоздаётся при каждом деплое и перезапуске, вместе с ней исчезает файл `db.sqlite3` —
то есть все аккаунты, пароли и очки стирались бы каждый раз, когда ты что-то пушишь.

Что сделать в панели Render, один раз:

1. **New → Postgres**, бесплатный план, регион тот же, что у сайта. Имя любое.
2. Дождаться, пока база создастся, и скопировать **Internal Database URL**
   (строка вида `postgresql://...`).
3. В настройках веб-сервиса → **Environment** добавить переменную:
   `DATABASE_URL` = скопированная строка.
4. Там же, если ещё нет, добавить:
   `DJANGO_DEBUG` = `0`
   `DJANGO_SECRET_KEY` = любая длинная случайная строка
   `DJANGO_CSRF_TRUSTED_ORIGINS` = `https://chiha-ge.onrender.com`
5. **Manual Deploy → Deploy latest commit.**

Проект сам переключается на Postgres, как только видит `DATABASE_URL`. Если переменной
нет — работает на SQLite, поэтому локально у тебя ничего не меняется и настраивать
ничего не нужно.

Build Command должен остаться таким (миграции создадут таблицы в новой базе, слова
загрузятся заново):

```
pip install -r requirements.txt && python manage.py migrate && python manage.py load_vocab && python manage.py collectstatic --noinput
```

Бесплатный Postgres на Render живёт 30 дней с момента создания, дальше его нужно
продлевать или переходить на платный — имей в виду, это их правило, не наше.

## Про пароли

Django хранит пароли только в виде хэша — ни в базе, ни в логах их нет, и восстановить
исходный пароль нельзя даже тебе. Восстановления по почте пока нет: почту мы не
спрашиваем. Если кто-то забудет пароль, аккаунт придётся заводить заново — либо
добавим сброс, когда появится отправка писем.

## Проверено браузером

Полный сценарий: аноним играет в «Буквы» и отмечает тему на тропе → регистрируется →
в кабинете сразу видит перенесённые очки («результатов перенесено: 1») → заходит на курс,
и локальные галочки уезжают на сервер → выходит, чистит localStorage целиком → входит
снова: очки на месте, галочка на тропе вернулась с сервера. Плюс проверены отказ при
неверном пароле, редирект гостя с `/kabinet/` на вход и вёрстка на ширине телефона.
